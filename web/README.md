# Кром в браузере — веб-версия (v0.2, D-044)

Сцена L_Krom для браузера на three.js: полёт и прогулка пешком. Собирается **без редактора UE** из тех же
данных, что и уровень: heightmap и маски, планы (`krom_plan`, `okolny_plan`, `landmarks_plan`, `finpark_plan`),
выгрузки Blender, `roads.json`, `city.json`, точки деревьев, мебели и кладбища.

- `web/` — исходники просмотрщика (в git): `index.html`, `app.js`, `walk.js` (столкновения), `.nojekyll`.
- `scripts/web_export.py` — сборка сцены в `build/web/` (не в git). Туда же копируется всё из `web/`, кроме `*.md`.
- `build/web/` — готовый статический сайт: все пути относительные, можно выкладывать как есть.
  `build/web/shots/` — снимки для истории, экспорт их не трогает.

## Собрать и открыть

```
.venv\Scripts\python scripts\web_export.py               # ≈3 мин; нужен node/npx (gltf-transform скачается сам)
.venv\Scripts\python scripts\web_export.py --only web    # только страница, текстуры и credits.json — 2 с
cd build\web
python -m http.server 8080
```

Открыть http://localhost:8080. Нужен интернет: three.js и three-mesh-bvh берутся с CDN jsDelivr.
Параметры адреса: `?view=olginsky` — точка обзора, `&mode=walk` — пешком, `&shot=1` — без интерфейса,
`&shadows=0` — без теней, `&dpr=1` — плотность пикселей.

Управление — кнопка «Управление» или `H`: WASD — идти или лететь, Q/E — вниз/вверх, Shift — быстрее,
колесо — скорость полёта, G — пешком/полёт, N — сквозь стены, V — следующая точка обзора.

## Выложить на GitHub Pages

**Рекомендация — ветка `gh-pages` без истории, а не папка `docs/`.** Почему:

- `docs/` в этом репозитории уже занята документами проекта, а Pages умеет только `/` или `/docs`.
- `.gitattributes` main отправляет `*.jpg` и `*.png` в Git LFS, а GitHub Pages отдаёт LFS-файлы как есть —
  текстовыми указателями. Текстуры на сайте сломались бы (серые здания). В ветке без истории `.gitattributes`
  нет, файлы ложатся в git целиком.
- Сборка — ≈20 МБ двоичных файлов; в истории main им не место (`build/` и так не в git).

Если основной репозиторий должен остаться закрытым (Pages для закрытых — только на платном тарифе), та же ветка
кладётся в отдельный открытый репозиторий только для сайта: меняется лишь `origin` у папки `build/gh-pages`.

**Опубликовано 2026-09-27:** https://dementev-dev.github.io/PskovKrom/ — ветка `gh-pages` репозитория
`dementev-dev/PskovKrom`, worktree `build/gh-pages` (в ней `.gitattributes` = `* -text`, LFS не действует, есть `.nojekyll`).

Один раз (git ≥ 2.42):

```
git worktree add --orphan -b gh-pages build/gh-pages
```

Каждая выкладка (PowerShell, из корня репозитория):

```
.venv\Scripts\python scripts\web_export.py
robocopy build\web build\gh-pages /MIR /XF .git .gitattributes   # зеркало сайта; .git — служебный файл worktree
cd build\gh-pages
git lfs ls-files                                           # должно быть пусто: LFS в ветке сайта не нужен
git add -A
git commit -m "site: сборка <дата>"
git push -u origin gh-pages
```

`robocopy` возвращает коды 1–7 при успехе — это не ошибка. На GitHub: Settings → Pages → Build and deployment →
Deploy from a branch → `gh-pages`, папка `/ (root)`. Адрес: `https://<пользователь>.github.io/<репозиторий>/`
(пути относительные — подкаталог не мешает). `.nojekyll` отключает обработку Jekyll.

Перед первой публикацией — проверить страницу «Источники» (см. ниже).

## Страница «Источники и лицензии»

Постоянный текст (OSM, FABDEM, Copernicus, WorldCover, программы) — в `web/index.html`, формулировки взяты из
`docs/REFERENCES.md` (S-02, S-18, S-31, S-33, S-46) и сверены с первоисточниками 2026-09-27:
openstreetmap.org/copyright, research-information.bris.ac.uk (FABDEM V1-2 — CC BY-NC-SA 4.0),
esa-worldcover.org (строка атрибуции и DOI), polyhaven.com/license (CC0).

Изменчивое — `credits.json`, его пишет `web_export.py`:
- **фото Commons по объектам** — из `build/*_refs/manifest.json` и `refs/photos/commons/manifest.json`
  (S-25). Берутся записи с автором, лицензией и страницей на commons.wikimedia.org; `copy_of` и повторы
  страницы пропускаются. Название объекта — словарь `PHOTO_OBJECTS` в скрипте; у новой папки `*_refs` без
  названия экспорт пишет предупреждение. Папки без манифеста (`belfry`, `kutekroma`, `cat`, `roads`, …)
  в список не попадают — на странице про них одна общая строка;
- **текстуры** — те, что лежат в `textures/`, авторы из `refs/textures/textures.json`.

## Пешком: столкновения (`walk.js`)

- Тело — капсула радиусом 0,35 м от 0,45 м над ногами до 1,85 м; глаз — 1,7 м. Что ниже 0,45 м (бордюр,
  ступень) — перешагивается, остальное выталкивает по горизонтали, вдоль стены скользишь. Радиус больше
  ближней плоскости камеры (0,25 м), поэтому камера не заглядывает в стену.
- Твёрдое: стены (`walls.glb`), мосты с перилами и устоями, дома `city.glb`, все герои. Пол — самая
  высокая поверхность под коленом: рельеф, дороги, настилы мостов, лестницы Финского парка, крыльца.
  Мебель, кладбище и деревья (инстансы) — не мешают.
- Вода — меш `water.glb` (урез −13,15 м и пруд выше плотины): если вода глубже 0,3 м над полом, шаг не
  делается (скольжение вдоль берега). Появившись в воде, выходишь к берегу по поверхности.
- Появление (G, выбор вида пешком): ближайшая свободная точка на земле или настиле — кольцами до 400 м;
  за краем рельефа — сначала к краю.
- BVH (three-mesh-bvh) строится лениво при первом подходе к мешу; движение — подшагами по 0,1 м.
- «Сквозь стены» (N, кнопка): без столкновений, по земле и по поверхности воды.

## Замеры

Ноутбук RTX 3060 Laptop, Chrome (Playwright, настоящий GPU через ANGLE/D3D11), 1280×720.

- **Загрузка** (от открытия до первого кадра, кэш выключен, `http.server` без gzip): localhost — 0,3 с;
  50 Мбит/с — 4,2 с; 10 Мбит/с — 15,4 с (спайк, 2026-09-27).
- **FPS** — 60, упор в vsync. Время кадра без vsync (`__krom.bench(40)`): 5–7 мс с тенями; пешком во дворе
  Крома — 5,4 мс, с новым `city.glb` фасадного генератора (273 тыс. треугольников) — 6,7 мс.
- **Столкновения**: `move()` пешком — 0,1–0,2 мс на кадр (максимум 0,4 мс). BVH строится при входе в пеший
  режим и по мере подхода: 110–280 мс всего; самый долгий — `city_1` (175 тыс. треугольников), 156 мс —
  разовая пауза при первом нажатии G (с `&mode=walk` — во время загрузки).
- В кадре 1,2–2,8 млн треугольников, 100–400 вызовов отрисовки. Больше всего стоят тени.

Проверено: стена двора (упор и скольжение), собор, дом города, перила Ольгинского моста с обеих сторон,
проход по мосту на берег Завеличья, берег Великой (стоп на урезе), лестница Финского парка (подъём
на 1,8 м, упор в поперечные перила площадки), все 11 точек обзора пешком.

## Оси

Проект: X — север, Y — восток, Z — вверх (левая система UE). three.js: (x, y, z) = (X, Z, Y), метры.
Это поворот, а не зеркало, и ровно так Blender выгружает героев в glTF: позиция (origin.x, земля, origin.y),
`rotation.y = −yaw`. Проверено на `SM_AxisTest.glb` и надписи «РОССИЯ НАЧИНАЕТСЯ ЗДЕСЬ»
(`shots/olginsky.jpg` читается слева направо).

## Чего нет

- Материалы UE (окна фасадов из HLSL, нормали, шероховатость, рябь воды) — в браузере цвет палитры и одна
  детальная текстура. Lumen, атмосфера, облака, время суток — нет, только «день».
- Деревья — кроны-многогранники, не модели `SM_Tree_*` (шаг 3 v0.2).
- Не выгружены: габионы, ночные фонари.
- Мосты берутся из `bridge_krom.py` через заглушку `unreal`; правильнее вынести геометрию в `bridge_mesh.py`.
- Телефоны не проверены (шаг 5 v0.2).
